## [2.0.0](https://github.com/OneLiteFeatherNET/Blackhole/compare/v1.0.0...v2.0.0) (2026-10-30)


### ⚠ BREAKING CHANGES

* **punishment:** generated client enums gain KICK; Velocity needs the kick-aware client.
* **security:** machine roles need an allow-listed azp; set BLACKHOLE_AUTH_MACHINE_CLIENTS_* before deploy, or PROXY, METRICS and DISCORD are refused.
* **security:** BLACKHOLE_AUTH_AUDIENCE (the API app client id GUID) and BLACKHOLE_AUTH_TENANT_ID are required outside dev and test; startup fails otherwise.
* **velocity:** the plugin no longer reads redisUri; operators must set nats.url and nats.credsFile (or NATS_URL and NATS_CREDS_FILE) and the proxy no longer needs access to Redis or Dragonfly.
* **auth:** the request fields source, resolvedBy, reviewerId, punishmentSource, the evidence source/createdBy and the ELO adjustment source are removed and ignored if sent. Punishment, revoke and evidence requests take an optional onBehalfOf, accepted only from the proxy.
* **auth:** every request needs "Authorization: Bearer <token>"; GET /health is the only public route. The Velocity plugin and the admin web UI do not send a token yet, their settings follow in the next two changes of this stack (velocity client credentials, web sign-in).
* **velocity:** the plugin now requires Velocity 4.3.0 or newer
* the ELO API reports scores per section instead of chatElo/gameplayElo, and the baseline, threshold and perma-ban-template settings under blackhole.elo are removed (sections own them).
* **database:** databases created by the Liquibase changelog are not migrated; drop and recreate them. No production data exists.
* **cache:** deployments must start on an empty PostgreSQL database.
* deployments must start on an empty PostgreSQL database.
* remove connector/signal integration framework ([#116](https://github.com/OneLiteFeatherNET/Blackhole/issues/116))
* **api:** AppealController's endpoints move from /v1/... to their bare path, versioned instead via the X-API-VERSION header or an api-version/v query parameter (default-version 1 covers callers that send neither).
* remove JWT/@Secured auth system ([#109](https://github.com/OneLiteFeatherNET/Blackhole/issues/109))
* **api:** tenant-scoped REST endpoints change shape (tenantId moves from body/claim to a URL path variable on several routes - see updated OpenAPI spec). JWTs no longer carry a tenantId claim, so tenant isolation is no longer enforced by the API - callers must not treat a role token as tenant-restricted anymore.
* the published backend artifact's Maven groupId changes from net.onelitefeather.blackhole to net.onelitefeather (artifactId blackhole-backend is unchanged). client and the newly-published velocity module already use/adopt net.onelitefeather.
* **database:** replace Flyway with Liquibase XML changelogs ([#101](https://github.com/OneLiteFeatherNET/Blackhole/issues/101))
* every existing endpoint moves from e.g. /punishment to /v1/punishment. Callers (Velocity plugin via the generated client, any connector integration) must regenerate/update against the new paths.
